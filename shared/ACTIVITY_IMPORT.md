# Активность и Аллюр: действующая модель, 21 сентября 2026

## Label Studio

Рабочий проект: **21 — «Активность и Аллюр»**. `LABEL_PROJECT_ID` выбирает
существующий проект. Воркер читает его конфигурацию, имена контролов и теги;
не создаёт проекты и не изменяет labeling config. Одна дорожка `videoLabels`:
Лежит, Сидит, Стоит, Шаг, Рысь, Галоп, Прыгает, Лестница, Нюхает, Чешется, Лает.

Импортируются завершённые записи с V2-анкетой, форматом `Аллюр/движение` или
`Активность`, видео и BLE. Идемпотентный ключ задачи — `woona:<recording UUID>`.
В `data` находятся `recording_id`, `dog_id`, `dog_profile_version_id`; в `meta`
— анкеты, исходные Drive ID/пути/SHA-256 и сведения о точности синхронизации.
Dashboard считает прогресс по реальному имени единственного timeline-контрола.

## Анкеты V2

`server/questionnaires.py` содержит точные соответствия всех 36 столбцов анкеты
собаки и 22 столбцов анкеты сессии, а также серверную схему V2. Источники:

- собака: `1V8tJqc0eD0yprxpad5peqb_sd-plvqskLb8ZZL1Srb8`, лист 0;
- сессия: `1HYfkYz6H8c78uWMiqflkEQgWy6JpsA5nRcCXReik0pM`, лист 0.

ID животного и кличка разделены. `numberOrName` сохраняет кличку для
совместимости транспорта; `animalId` — внешний ID. Диагнозы, категории,
хромота, препараты, анамнез и специалист — отдельные поля. Поверхности и
планировавшиеся форматы записи допускают несколько ответов. Необязательные
ответы могут отсутствовать. Невалидные введённые числа отклоняются.

V1 остаётся доступной для истории. Новые UI Android/iOS создают V2.
Технические UTC/monotonic времена остаются отдельными от ручных ответов.
При live-записи дата/начало/окончание/длительность заполняются приложением;
ID животного берётся из выбранной карточки. Собака и версия профиля связываются
с записью внешними ключами, а не строковым совпадением кличек.

В JSON V2 сохранены прежние транспортные поля для совместимости локального
хранилища. Устаревшие status/measurement-поля не являются вопросами нового UI
и не участвуют в маршрутизации. Версия анкеты отправляется отдельно от версии
manifest/sync, включая iOS.

## Связи и аудит

Миграция `0003_source_provenance.py` добавляет:

- `dog_external_ids`: уникальный `(namespace, external_id)` → `dogs.id`;
- `source_imports`: исходная папка/файлы → `recordings.id`, либо причина пропуска;
- `source_survey_rows`: исходные и нормализованные ответы, ссылки на собаку,
  immutable profile version и запись, результаты проверки.

Один animal ID не может создать две собаки. При конфликте API возвращает 409
с существующим `dogId`; клиент должен синхронизировать и выбрать эту карточку.
Импорт использует исходный recording UUID и отдельное отозванное техническое
устройство без рабочего токена. Повторный импорт проверяет неизменность
происхождения и не создаёт новых записей/артефактов.

## Пакет Drive

Папка `1W2LGVqKdi7ckSonGUn7SHSvy1P54n5jE` сохранена на сервере в
`/srv/woona/drive-activity-2026-09-21`. Скачивание `tools/download_activity_drive.py`
хранит файлы по Drive ID, поэтому одинаковые имена не перезаписываются.
ЭКГ исключены; неполные/неоднозначные комплекты остаются в аудите.

Проверка включает анкеты, собаку/номер/дату сессии, наличие и SHA-256 всех
артефактов, дубли видео, FFprobe, технические времена и явные расхождения
длительности. CSV и inventory снимка неизменны в рамках запуска. Старый ZIP
не приравнивается к современной записи без проверяемых метаданных.

Команда внутри контейнера API с read-only snapshot и доступным каталогом отчёта:

```sh
python -m server.import_activity /snapshot /surveys          # план и отчёт
python -m server.import_activity /snapshot /surveys --apply  # тот же план + БД
python -m server.label_sync --once
```

`/surveys` должен содержать `dogs.csv`, `sessions.csv`, `inventory.json`;
`/snapshot` — `manifest.json`, `video-probes.json`, исходные файлы.
