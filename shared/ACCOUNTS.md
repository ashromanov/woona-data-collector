# Аккаунты операторов — 1.3.5

Аккаунт выбирается уникальным строковым идентификатором, например `anna-ecg`.
Паролей, регистрации по почте и отдельной авторизации пользователя нет.
Идентификатор содержит 1–64 латинских букв, цифр, точек, дефисов или
подчёркиваний и начинается с буквы или цифры. Пробелы по краям удаляются,
регистр приводится к нижнему: `Anna-ECG` и `anna-ecg` — один аккаунт.
Ввод нового идентификатора создаёт аккаунт; ввод существующего открывает его.
Любой человек с настроенным техническим доступом к серверу и тем же
идентификатором может открыть и изменять данные этого аккаунта.

## Данные и приложение

У собаки один аккаунт. Все её сессии активности и сердцебиения, анкеты и
контрольные файлы наследуют эту привязку. Связь хранится в `dogs.account_id`;
дублировать владельца в каждой сессии не требуется.

При выборе аккаунта Android/iOS восстанавливают связанные серверные анкеты
собак и сессий. Исходные файлы скачиваются имеющимся отдельным механизмом.
Анкеты сессий с незавершённой серверной выгрузкой тоже отображаются; загрузку
исходных файлов завершает исходное устройство.
Локальная работа и файлы других аккаунтов сохраняются при переключении;
выгрузка использует аккаунт собаки, а не текущий выбор на экране.
Старые собаки и их сессии остаются без аккаунта. Оператор привязывает собаку
вручную; вместе с ней привязываются все её сессии. Перенос собаки из уже
назначенного аккаунта в другой не поддерживается. На новом телефоне для
привязки старой собаки сначала примените пустой идентификатор, чтобы загрузить
непривязанные анкеты, затем выберите аккаунт и нажмите кнопку привязки собаки.

Анкеты сохранённых сессий можно редактировать после записи. Для серверной
сессии сохранение требует связи с сервером и аккаунта. Версия анкеты,
показанной при открытии редактора, передаётся серверу: устаревшая правка
получает конфликт, а не перезаписывает новые ответы. При конфликте нужно
обновить данные и открыть редактор заново.

Редактирование сохраняет исходные файлы, временные метки захвата, собаку,
вид сессии и фактический выбор видео. Receipt загрузки артефактов и `sync.json`
остаются исходными. Актуальные ответы хранятся в метаданных сессии на сервере.

## API

Существующий Bearer-токен устройства остаётся обязательным. Заголовок
`X-Woona-Account: anna-ecg` выбирает аккаунт для списков, чтения, выгрузки,
скачивания и редактирования. Без заголовка доступны только непривязанные
данные. Идентификатор не является паролем или отдельным секретом.

- `PUT /v1/accounts/{identifier}` — создать/открыть, ответ `{identifier}`.
- `PUT /v1/dogs/{dog_id}/account` с `{accountId}` и заголовком выбранного
  аккаунта — явно привязать старую собаку. Повтор той же привязки безопасен;
  другой аккаунт получает `409 dog_account_conflict`.
- Новые собаки получают аккаунт из заголовка при обычной выгрузке профиля или
  manifest сессии. Выгрузка не присваивает существующую непривязанную собаку.
- `GET /v1/dogs` и подробности собаки возвращают `accountId` (или `null`).
  Списки и подробности сессий доступны в аккаунте их собаки; подробности
  сессии дополнительно возвращают `questionnaireRevision` (начиная с 1).
- `PUT /v1/recordings/{id}/questionnaire` принимает
  `{expectedRevision, questionnaire}` и возвращает полные актуальные
  подробности сессии. `409 questionnaire_revision_conflict` содержит
  `serverRevision`. Правки проходят существующую проверку анкеты.

## Обновление

Миграция `0007` идёт после `0006`, создаёт аккаунты, добавляет nullable
`dogs.account_id` и `recordings.questionnaire_revision`. Существующие данные
не распределяются автоматически. Перед назначением аккаунтов обновите сервер
и оба клиента: старые клиенты без заголовка видят только непривязанные данные.
Административная панель сервера сохраняет доступ ко всему набору данных.

Проверка API: `python -m unittest -v server.tests.test_accounts` в тестовом
серверном окружении. Тесты проверяют изоляцию списков и файлов, явную привязку,
работу второго устройства, конфликт правок и неизменность исходных файлов.
