# Сессии сердцебиения

Связь данных: **существующая собака → сессия → исходные файлы**.
Карточка собаки не получает новых медицинских полей.

В Android/iOS перед записью выбирается «Активность» или «Сердцебиение».
«Активность» использует прежнюю анкету; «Сердцебиение» — отдельную анкету
после остановки записи ошейника. Видео для сердцебиения выключено по умолчанию
и может быть включено оператором. Шесть основных вопросов находятся в одном
потоке, без предвыбранных ответов. Незавершённая анкета оставляет запись
локально и доступна из списка сессий; выгрузка начинается после её сохранения.

Анкета хранится в `recordings.session_questionnaire.heartQuestionnaire`;
`sessionKind: "heart"` отличает такие сессии от старых записей.
Внешняя анкета сессии остаётся версии 2; самостоятельная анкета по сердцу —
версии 1. Для каждого выбранного ответа сохраняются `key` и `text`.
Контракт: `docs/target-server-plan/models/heart-questionnaire.schema.json`.
«Неизвестно» допустимо в каждом вопросе. Поля диагноза и препарата
необязательны; контрольный артефакт или ЧСС со временем обязательны при выборе
соответствующего способа. «Нет» и «Неизвестно» в факторах выбираются отдельно.
Существующий контрольный файл ЭКГ/Polar подставляет способ и привязку в форму;
оператор проверяет ответ перед сохранением.

Идентификаторы собаки/сессии и UTC-границы берутся из технических метаданных
записи. Ответы описывают состояние, условия и качество данных, без заключения
об аритмии. Одиночная ЧСС пригодна для сравнения среднего темпа, а не ударов.

## Контрольные файлы

В списке записанных сессий Android/iOS доступно «Добавить ЭКГ / ЧСС / интервалы».
В серверном `/dashboard` есть ссылка «Добавить ЭКГ / ЧСС» у сессии.
Оператор выбирает исходный файл, тип (`ecg`, `heart_rate`, `rr`), устройство,
начало/окончание контрольной записи с часовым поясом и необязательные примечания.

`referenceMetadata.offsetFromRecordingMs` — поправка к UTC-меткам таргета:
`aligned_utc = target_utc + offsetFromRecordingMs`.
Пустое значение означает, что поправка не измерена; ноль не подставляется.
Исходные файлы не преобразуются. Поддерживаются в том числе CSV, JSON,
текстовые и бинарные экспорты устройств; автоматического извлечения времён из
неизвестных форматов нет. В браузере размер ограничен 256 МиБ, поскольку
Web Crypto рассчитывает SHA-256 всего файла в памяти; большие файлы загружаются
через мобильный поток с потоковым хешированием.

Файлы остаются на диске сервера; в PostgreSQL сохраняются анкета, связь с
сессией, тип, источник, временная привязка, размер и SHA-256.
Миграция `0004_heart_references` расширяет существующую таблицу артефактов.
Выгрузка возобновляется через имеющиеся HEAD/PATCH/complete и проверку SHA-256.
`POST /v1/recordings/{id}/references` регистрирует новые контрольные файлы
после первой выгрузки. Любое действующее устройство может добавить файл к
общей сессии; незавершённую загрузку продолжает зарегистрировавшее его
устройство. Серверная форма использует существующую авторизацию Label Studio
и проверяет источник запросов на запись.

Первоначальный receipt подтверждает файлы захвата ошейника; поздние контрольные
артефакты имеют собственные проверки и статусы. Они не меняют первоначальный
receipt. Восстановление включает исходные файлы и метаданные; экспорт ZIP
включает исходные файлы и анкету.
**Сердечные сессии и контрольные артефакты не отправляются в Label Studio**,
даже если у сессии есть видео.

## Проверки

```sh
./android/tools/check.sh fast
./android/tools/check.sh full
cd shared
docker compose config -q
docker compose exec -T api python -m unittest -v server.tests.test_heart
```

iOS: `WoonaDataTests.testHeartAnswersReferencesAndRestart` запускается на
macOS/Xcode вместе с существующими тестами. Проверки на Linux и эмуляторе
не подтверждают работу реального ошейника, камеры и синхронизацию устройств.
